# MenuAll E2Eテスト計画

- 文書バージョン: 0.2
- 対象: macOS 14以降
- 自動テスト: `MenuAllUITests`
- 実機テスト: ノッチ付きMacを含む検証端末

## 1. 方針

E2Eテストを次の2層に分ける。

1. 権限に依存しない自動UI E2E
   - 起動、権限案内、再確認、システム設定ボタン、終了を毎回同じ条件で確認する。
   - `XCUIApplication.launchEnvironment`でテスト条件を注入し、実際のTCC状態やシステム設定を変更しない。
2. 実機E2E
   - Accessibility API、ノッチ、他アプリ、表示状態の実変更、署名・公証済み配布物が必要な項目を確認する。
   - 端末情報、対象アプリ、画面収録またはスクリーンショット、ログを証拠として残す。

自動UI E2Eは外部ネットワークを使用せず、利用者の権限状態を変更しない。

## 2. アプリ側のテスト契約

### 2.1 起動環境変数

| キー | 値 | 動作 |
| --- | --- | --- |
| `MENUALL_UI_TESTING` | `1` | DebugビルドでのみUIテストフックを有効化 |
| `MENUALL_UI_TEST_ROUTE` | `onboarding` | ステータス項目を経由せず初回案内を表示 |
| 同上 | `popover` | 実物の`NSPopover`を画面内のテスト専用アンカーへ空状態で表示 |
| `MENUALL_UI_TEST_ACCESSIBILITY_SEQUENCE` | `denied` | 権限未許可を固定再現 |
| 同上 | `denied,granted` | 初回は未許可、再確認後は許可済みを再現 |
| `MENUALL_UI_TEST_SUPPRESS_EXTERNAL_NAVIGATION` | `1` | システム設定ボタンの外部遷移だけを抑止 |
| `MENUALL_UI_TEST_VISIBILITY_FIXTURE` | `three-categories` | 非表示、表示中、位置不明、非対応の決定的な項目を注入 |
| `MENUALL_UI_TEST_VISIBILITY_CHANGE_SCENARIO` | `success` | 表示変更と再観測の成功を再現 |
| 同上 | `failure` | 変更失敗と元状態の維持を再現 |
| 同上 | `unsupported` | 理由付きの操作不可を再現 |
| 同上 | `delayed` | 変更中表示と遅延後の成功を再現 |

環境変数の解釈は `MenuAll/Support/LaunchEnvironment.swift` に閉じ込める。Releaseビルドでは `MENUALL_UI_TESTING` が無効になる。

### 2.2 アクセシビリティ識別子

画面実装では次の識別子を設定する。

| 対象 | 識別子 |
| --- | --- |
| 初回案内のルート | `menuall.onboarding` |
| メインポップアップのルート | `menuall.popover` |
| ポップアップのヘッダー | `menuall.popover.header` |
| 空状態 | `menuall.popover.empty` |
| 再読み込み | `menuall.refresh` |
| 設定 | `menuall.settings` |
| 権限が必要な理由 | `menuall.permission.reason` |
| 未許可状態 | `menuall.permission.state.denied` |
| 許可済み状態 | `menuall.permission.state.granted` |
| システム設定を開く | `menuall.permission.open-system-settings` |
| 再確認 | `menuall.permission.recheck` |
| 終了 | `menuall.quit` |
| 項目の元メニューを開く | `menuall.item.<id>.open` |
| 項目の表示切り替え | `menuall.item.<id>.visibility-toggle` |
| 項目の非対応理由 | `menuall.item.<id>.visibility-unsupported` |
| 表示変更エラー | `menuall.visibility.error` |
| 直前変更の案内 | `menuall.visibility.undo` |
| 変更を取り消す | `menuall.visibility.undo.action` |

表示文言ではなく識別子で要素を取得し、文言変更やローカライズでE2Eが壊れないようにする。

### 2.3 製品コードへの統合点

1. 起動コーディネーターは `LaunchEnvironment.uiTestRoute == .onboarding` の場合、通常のステータス項目クリックと同じ初回案内を直接表示する。
2. 権限サービスは確認回数を0から保持し、先に `LaunchEnvironment.accessibilityAuthorizationOverride(atCheckIndex:)` を参照する。値が `nil` の場合だけ `AXIsProcessTrusted` を使う。
3. 「再確認」操作のたびに確認回数を増やして状態を再取得する。
4. システム設定を開く処理は `LaunchEnvironment.shouldSuppressExternalNavigation` が `true` の場合だけ外部遷移を省略する。ボタンのUIイベント自体は通常どおり処理する。
5. `LaunchEnvironment`を画面から直接参照せず、起動・権限・外部遷移の境界でのみ参照する。
6. 表示変更は`MenuBarVisibilityChanging`のfakeをAppDelegateで注入し、画面から起動環境変数を直接参照しない。
7. fakeでも変更要求と再観測を別段階にし、製品と同じく再観測後だけ成功表示へ進む。

## 3. 自動UI E2E

| ID | シナリオ | 合格条件 |
| --- | --- | --- |
| AUTO-01 | 未許可で初回案内を起動 | 理由、未許可状態、設定、再確認、終了が3秒以内に表示される |
| AUTO-02 | 未許可から再確認 | 再確認後に許可済み状態へ3秒以内に変わる |
| AUTO-03 | システム設定ボタン | テスト時は外部遷移せず、案内画面とアプリが維持される |
| AUTO-04 | 権限案内から終了 | クリック後3秒以内にアプリが終了する |
| AUTO-05 | 許可済みでポップアップを起動 | ヘッダー、空状態、再読み込み、設定、終了が3秒以内に表示される |
| AUTO-06 | ポップアップから設定 | 設定画面が3秒以内に表示される |
| AUTO-07 | ポップアップから終了 | クリック後3秒以内にアプリが終了する |
| AUTO-08 | 非表示→表示 | トグル操作後、成功確認を経て項目が表示中セクションへ移り、取り消しが表示される |
| AUTO-09 | 表示→非表示 | トグル操作後、成功確認を経て項目が非表示セクションへ移る |
| AUTO-10 | 表示変更失敗 | 項目が元セクションに残り、再試行可能なエラーが表示される |
| AUTO-11 | 非対応と位置不明 | トグルが無効で、項目ごとの理由を取得できる |
| AUTO-12 | 元メニュー操作との分離 | 元メニューを開いても表示状態が変わらない |
| AUTO-13 | 表示変更の取り消し | 取り消し操作後、元の状態を再観測して元セクションへ戻る |

実行例:

```bash
xcodebuild test \
  -project MenuAll.xcodeproj \
  -scheme MenuAll \
  -destination 'platform=macOS' \
  -only-testing:MenuAllUITests
```

## 4. 実機E2Eの共通条件

- テスト前にOSバージョン、Macモデル、CPU、内蔵・外部画面、解像度、ノッチ有無を記録する。
- MenuAllのバージョン、Gitコミット、署名状態を記録する。
- 対象アプリ名とバージョンを記録する。
- 個人情報や通知内容が映らないテスト用状態を用意する。
- 各ケースで開始前、操作中、結果のスクリーンショットまたは画面収録を残す。
- MenuAllのOSLogを保存する。ログに取得したメニュー名などの利用者データを恒久保存しない。

証拠の推奨ファイル名:

```text
docs/evidence/e2e/<実施日>/<ケースID>/environment.md
docs/evidence/e2e/<実施日>/<ケースID>/result.md
docs/evidence/e2e/<実施日>/<ケースID>/screen-recording.mov
docs/evidence/e2e/<実施日>/<ケースID>/menuall.log
```

`result.md`には実施者、開始・終了時刻、手順ごとの結果、期待値との差、最終判定を記録する。

## 5. Accessibility権限E2E（SP-04）

### MANUAL-AX-01 未許可

前提: システム設定の「プライバシーとセキュリティ > アクセシビリティ」でMenuAllが許可されていない。

1. MenuAllを起動する。
2. 必要な理由、現在の状態、次の操作を確認する。
3. 「再確認」を押す。
4. 「システム設定を開く」を押す。

合格条件:

- 無反応や空の一覧にならず、未許可と明示される。
- 権限が必要な理由が表示される。
- 再確認後も未許可状態を正しく表示する。
- システム設定のAccessibility設定画面へ移動できる。
- 案内画面からMenuAllを終了できる。

### MANUAL-AX-02 許可済み

1. システム設定でMenuAllを許可する。
2. MenuAllへ戻り「再確認」を押す。

合格条件:

- 2秒以内に許可済み表示へ変わる。
- アプリの再起動が必要な場合は、その必要性と手順が明示される。
- 一覧取得へ進める。

### MANUAL-AX-03 拒否・取り消し後

1. 許可済みの状態で一覧を表示する。
2. システム設定でMenuAllの許可をオフにする。
3. MenuAllへ戻り、再読み込みまたは再確認を行う。

合格条件:

- クラッシュせず2秒以内に未許可として案内する。
- 古いAX要素を操作可能として表示し続けない。
- 再許可の手順と終了操作を利用できる。

## 6. メニューバー列挙E2E（SP-01）

対象はシステム項目だけに偏らない代表的な5アプリ以上とする。対象例は、実施端末に導入済みのチャット、同期、セキュリティ、開発支援、ユーティリティから選ぶ。

1. 対象アプリを起動し、各ステータス項目が画面上に見える状態にする。
2. MenuAllを開いて再読み込みする。
3. 所有アプリ名または項目名、アイコン代替、取得状態を照合する。
4. 対象アプリを1つ終了・再起動し、一覧の変化を計測する。

合格条件:

- 5アプリ以上について、名称または所有アプリを識別できる。
- 1項目が取得失敗しても、他の項目を表示・操作できる。
- 起動・終了による増減を原則2秒以内に反映する。
- 取得失敗数と不明状態を「すべて取得済み」と誤認させない。

証拠には対象アプリごとの「期待した識別情報」「取得結果」「更新時間」「失敗理由」を表形式で残す。

## 7. ノッチ裏項目E2E（SP-02）

前提: ノッチ付き内蔵画面を使用し、メニューバー常駐項目を増やして1件以上を画面上で見えない状態にする。

1. ノッチ前後の項目配置が分かる画面収録を開始する。
2. 対象項目が通常のメニューバーから操作できないことを確認する。
3. MenuAllを開く。
4. 隠れている項目の分類と識別情報を確認する。
5. 解像度または起動アプリを変え、同じ項目を表示状態に戻して比較する。

合格条件:

- 画面上で非表示の項目を1件以上一覧へ表示できる。
- 「非表示」「表示中」「判定不明」を誤って断定せず区別する。
- 表示状態を変えた後、原則2秒以内に分類が更新される。

証拠には同一項目の非表示時・表示時の画面、AX属性の差分、MenuAll上の分類を残す。外部ディスプレイがある場合は内蔵画面との比較も記録する。

## 8. 元項目操作E2E（SP-03）

異なる実装を持つ3アプリ以上を対象にする。

1. MenuAllを開く。
2. 対象項目を選択する。
3. MenuAllのポップアップと元項目のメニュー状態を確認する。
4. メニュー内の破壊的でない操作を1つ実行する。
5. 対象アプリを再起動し、古い参照が残らないことを確認する。

合格条件:

- 3アプリ以上で、選択した元項目のメニューまたは対象操作が起動する。
- 別項目を誤操作しない。
- MenuAll自身のポップアップが操作を妨げない。
- 無効になったAX参照ではクラッシュせず、再取得または操作不可を通知する。
- 1アプリの失敗で他アプリの操作が不能にならない。

証拠には対象アプリ、選択したMenuAll項目、実際に開いたメニュー、所要時間、AXアクション、成否を記録する。

## 9. ステータス項目・性能・配布E2E

### MANUAL-VIS-01 表示／非表示の双方向切り替え（VG-01〜VG-03）

前提: Ice、Bartender等の同種管理アプリを終了し、開始前のメニューバー配置を記録する。最初の対象はMenuAllがテスト用に所有する専用fixtureとし、起動用のMenuAllアイコンや他の利用者項目を移動しない。

1. 対象が表示中であることをOS上とMenuAll上で確認する。
2. MenuAllの「メニューバーに表示」トグルをオフにする。
3. 対象が実メニューバーから非表示になり、MenuAllの非表示セクションへ移ることを確認する。
4. 同じトグルをオンにする。
5. 対象が実メニューバーへ表示され、MenuAllの表示中セクションへ移ることを確認する。
6. 元メニューを開く操作を行い、表示状態が変わらないことを確認する。

合格条件:

- 両方向とも要求から2秒以内に実状態と一覧分類が一致する。
- UIは再観測前に成功を確定しない。
- 対象以外の項目の順序と表示状態が変わらない。
- 元メニュー操作と表示切り替えを誤操作しない。

### MANUAL-VIS-02 失敗とrollback（VG-02）

1. 専用fixtureで変更後の再観測失敗または対象消失を再現する。
2. timeoutまでの進行表示と操作抑止を確認する。
3. 自動rollback後の実状態と一覧を確認する。

合格条件:

- timeoutまたは観測失敗を成功として表示しない。
- 元状態への復元を再観測できる。
- 復元にも失敗した場合は変更機能を停止し、状態不明と具体的な復旧案内を表示する。
- 1項目の失敗後も他項目の閲覧と元メニュー操作を継続できる。

### MANUAL-VIS-03 競合と非対応（VG-04）

1. Ice等の検出対象を起動した状態でMenuAllを開く。
2. 表示切り替えが無効で、競合理由が表示されることを確認する。
3. 競合アプリを利用者の操作で終了し、MenuAllを再読み込みする。
4. 固定システム項目、一意照合できない項目、位置不明項目を確認する。

合格条件:

- 競合中にCGEventによる変更を送信しない。
- MenuAllが競合アプリを終了、設定変更、アンインストールしない。
- 競合終了後は再取得により可否を再判定する。
- 公開APIで安全に保証できない項目は理由付きで操作不可となり、他項目は利用できる。

### MANUAL-UI-01 ステータス項目

- DockにMenuAllが常時表示されない。
- MenuAllのステータス項目を1クリックするとポップアップが開く。
- 項目数が多い場合にスクロールできる。
- 再読み込み、設定、終了へアクセスできる。
- キーボード操作とVoiceOver読み上げで同じ操作に到達できる。

### MANUAL-PERF-01 起動性能

通常利用状態でステータス項目クリックからポップアップの初期内容表示までを20回計測する。

合格条件: 各回500ms以内を目標とし、中央値と最大値を記録する。キャッシュ表示後の再取得時間は別に記録する。

### MANUAL-DIST-01 署名・公証済みビルド（SP-05）

1. Developer ID署名・Hardened Runtime有効でアーカイブする。
2. 公証し、stapleした配布物を検証端末へコピーする。
3. Gatekeeper経由で起動し、MANUAL-AX-02、SP-01、SP-03、MANUAL-VIS-01〜03の主要フローを実施する。

合格条件: 警告回避操作なしで起動でき、署名・公証済み配布物でも主要機能が動作する。

## 10. 判定

各SPとVGは「合格」「条件付き合格」「不合格」「追加検証」のいずれかで判定する。SP-02、SP-03、VG-01、VG-02またはVG-03が不合格の場合は、MVPの中心価値、対応対象、表示管理の提供範囲を見直す。
